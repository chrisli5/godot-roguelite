# Project: Action Roguelite (Godot 4, GDScript)

Last synced with code commit: `a7ec989`. Update this line whenever this file changes.

Auto-attack action roguelite (Vampire Survivors-style combat) with a Slay the Spire-style room map.
Engine: Godot 4.x. The code uses `@abstract` and typed Dictionaries, so assume 4.5 or newer.
Elemental infusions (Fire, Frost, Lightning, Wind, Earth) are socketed into ability slots and drive evolutions.

## Code style
- Tabs for indentation. Static typing everywhere (`var x: int`, typed arrays and dictionaries).
- One `class_name` per script. `##` doc comments on public methods.
- Data lives in Resources (`.tres`), not hard-coded constants. Tunable numbers are `@export`.
- Tags are an enum (`Tags.Type`), never strings.
- No new `print()` calls in hot paths (damage, stat recalculation, invalidation).

## Architecture rules (do not break these)
- **Component isolation.** Child components never hold references to sibling nodes. The parent wires them with signals and method parameters. Entity, Player and Ability are the mediators.
- **EventBus** (autoload) is the global signal hub. `EventBus.active_player_instance_id` is how systems find the player; call `instance_from_id()` on it.
- **Slots.** Slot 0 is the Character Core (player stats). Abilities occupy slots 1-4 (`AbilityContainer.MIN_SLOT` / `MAX_SLOT`).
- **Ability pipeline.** `AbilityData` selects: deployment anchor, geometry driver, optional payload driver, stats profile. The ability runs anchor -> spatial query -> geometry driver. Evolutions swap those strategy nodes via `execute_ability_evolution`.
- **Stats.** `StatsContainer` caches lazily with dirty flags. Call `get_final_stat_value(stat_type)` with ONE argument. Tags come from the container's own `TagComponent`, never from the caller.
- **Tags.** `TagComponent` compiles three layers: `base_tags` (replaced from `AbilityData.structural_tags` in `Ability.swap_runtime_strategies`; an empty list logs a warning and leaves the tags unchanged), infusion tags (rebuilt from the run ledger, never stored on the component), and refcounted temporary tags from status effects. `get_permanent_tags()` is base plus infusion tags; `get_active_tags()` adds temporary tags. Stat cards, statuses, bursts and draft eligibility use permanent tags only; damage payload tags use active tags.
- **Run ledger.** `RunLedgerComponent` (on the Player) is the single source of truth for upgrades. Aggregate with `get_modifier_totals(slot, tags, stat)`, which returns `Vector3(flat, percent, multiplicative)`. Do not create temporary modifier resources in hot paths. Slot-specific purchases (infusions, Overclock) are stored under the key `"<upgrade_id>::slot_<n>"` and win over the plain key. An infusion's level for (slot, element) is stored nowhere else: `get_infusion_level(slot, element)` and `get_infusion_levels(slot)` sum the slot-specific tiers of cards whose `UpgradeDefinition.category` is `INFUSION` (never the id prefix). `InfusionTrackerComponent` holds no levels; it reads the ledger through `configure_slot_context(slot, ledger)`. Build and parse slot keys only through `PurchaseKey.make` and `PurchaseKey.parse`; the stored key format is unchanged. `get_card_tier(def, slot, permanent_tags)` is the single answer to whether a card applies to a slot. A `GLOBAL_TAG_MATCH` card applies only to an ability whose permanent tags contain ALL of the card's `target_tags` (Task AR; an empty list matches nothing), decided by `UpgradeDefinition.matches_permanent_tags`, which both the ledger and the draft pool use. `StatsContainer` invalidates stats by asking it, so it holds no scope rules of its own. Overclock is derived the same way: `is_overclocked(slot)`; no component stores it.
- **Shared payloads.** A `CombatPayload` is shared by every projectile in a volley. Duplicate it before any per-hit mutation. Status effect resources are templates: never mutate them, keep runtime state in a separate per-application object (`StatusEffectInstance`). Per-hit state (for example a pierce count) lives on the projectile, never on the payload.
- **Driver library.** Geometry drivers: projectile (Targeted = nearest enemy, Straight = player movement direction, MouseAim; all use the fan helper with `PROJECTILE_AMOUNT` and 15 degree spread), area (RadialPulse, LinearSweep, Fissure, ConvergingVortex, ChainLink), persistent (OrbitingRing). Trajectories (`MovementStrategy`): Vector (default), Homing, Boomerang, SineWave, Tornado. The only payload driver is `MissileHitPayload`, which just sets the trajectory scene. Every geometry ends in `HurtboxComponent.take_hit(payload)`, so statuses apply from any shape. An evolution may change family (projectile -> area).
- **Driver stats.** Each driver reads specific stats from the ability's profile, and a missing stat reads 0.0: no `PROJECTILE_AMOUNT` means no shots, no `DURATION` kills a projectile instantly, no `CHAIN_RADIUS` means no chain. `mutate_base_profile` replaces the whole profile, so every evolution's stats profile must carry every stat its drivers read, plus `BASE_DAMAGE`, `COOLDOWN`, `CRIT_*`, `DOT_DAMAGE`, `STATUS_DURATION` and `STATUS_RAMP_CAP`, plus `AOE_RADIUS` for projectile and orbit abilities (it is their hitbox radius; Task G), plus `REACH_BONUS`, `SPEED_BONUS` and `STATUS_MAGNITUDE_BONUS` entries at 0.0 so Earth, Wind and status magnitude cards apply (Tasks X and AR). A modifier on a stat that is missing from the profile has no effect (the stat reads 0.0), which is why Arcane Bolt's profile needed `STATUS_RAMP_CAP: 0.0` before Fire's cap bonus reached Burn.
- **Geometry contract.** Every concrete geometry driver declares `get_family()` (one of `GeometryDriver.FAMILIES`: moving_hitbox, area_instant, area_stepped, chain, timed), `get_reach_stats()` (the stats Earth scales) and `get_speed_stats()` (the stats Wind scales; empty if the geometry has no speed concept). Fire, Frost and Lightning reach every geometry that ends in `HurtboxComponent.take_hit`. A new geometry scene without a declared family fails the logic test, and the table in GDD section 1 must list it. Only the radial pulse and the linear sweep were re-parented (under `AreaGeometry`, Task Y); no other geometry class moved. Reach stats are scaled by the `REACH_BONUS` stat and speed stats by `SPEED_BONUS`, through one shared helper (`StatBonus`, Task X): value * (1 + bonus). Earth's card modifies only `REACH_BONUS` and Wind's only `SPEED_BONUS`; both default to 0.0, and a profile must carry both keys or Earth and Wind do nothing for that ability. `QUERY_RADIUS` (targeting range) is never scaled. Chain link and fissure deliver in steps (`SequencedGeometry`, Task Z): `step_delay` seconds apart (0 means instant), divided by `1 + SPEED_BONUS`; every stat they need is read at cast time, and the geometry emits `delivery_finished` once, after the last step, which is when the ability's cooldown restarts.
- **Enemy queries.** The enemy hurtbox mask and the per-query result limit are constants in `CombatPhysics` (`ENEMY_HURTBOX_MASK`, `MAX_QUERY_RESULTS`), defined once. Geometries, burst shapes and zones find enemies through `SpatialQuery.query_enemy_hurtboxes` (or `GeometryDriver._enemy_hurtboxes_in`), which skips player hurtboxes and an excluded id. No driver declares its own mask or buffer. The limit is 32, so a shape never hits more than 32 enemies; raising it is a one-line change.
- **Crit.** Rolled once per hit, not per cast (Task AL, decided Oct 26). `generate_hit_payload` rolls nothing: it stores `CombatPayload.crit_chance_snapshot`, `crit_multiplier_snapshot` and `crit_dot_share_snapshot` and sets `final_damage` to `BASE_DAMAGE * damage_scale` (pre-crit). `HurtboxComponent.take_hit` first calls `CombatCalculations.resolve_hit_crit(payload)`: it returns the same payload on a miss (also when the chance is 0 or less, or the payload `is_burst`) and a duplicate on a crit, with `final_damage` times the multiplier, `is_critical_hit` true and, when the share is above 0, `dot_damage_snapshot` times `1 + (multiplier - 1) * share` (Plasma, per critting hit). The shared cast payload is never mutated and always has `is_critical_hit` false. Bursts qualify and `hit_received` is emitted from the resolved payload, so ON_CRIT bursts fire per critting hit (still capped by `max_per_cast`) and a burst's damage includes the hit's crit. A fan, chain or pulse can mix crits and plain hits. Ticks never roll a crit.
- **Impact bursts.** A burst is secondary area damage centered on an enemy that was just hit. It is not an ability (no slot, cooldown, anchor, stats profile or tags). Parts: `ImpactBurstDefinition` (a resource: `burst_id`, `trigger` ON_HIT or ON_CRIT, `shape`, `damage_fraction`, `per_enemy_bonus`, `per_enemy_bonus_cap`, `carried_status_tags`, `required_target_tag`, optional `effect_scene`; a null `shape` makes an effect-only burst that just spawns its effect), `BurstShape` (abstract; `find_targets(origin, stats, space_state, exclude_instance_id)` only finds targets, and may return the same hurtbox twice) with `CircleBurstShape` (radius = `AOE_RADIUS * radius_multiplier`), and the static runner `ImpactBurst.run`, which owns every rule. A card carries a definition in `UpgradeDefinition.impact_burst_payload`. The ledger resolves definitions for a slot (same scope rules as statuses, deduplicated by `burst_id`), `generate_hit_payload` stores them on `CombatPayload.impact_bursts` at cast time, and `HurtboxComponent.take_hit` runs each matching one deferred (physics callbacks may not allow spatial queries). Rules: the origin is the hit enemy's position, copied at hit time; the primary target is excluded; each definition has `max_per_cast` (0 = unlimited), enforced through the cast's shared `CastBudget` (a `Resource` on `CombatPayload.cast_budget`, spent by `HurtboxComponent.take_hit` under the key `definition.get_instance_id()`; only a burst that qualifies spends, a null budget is unlimited; `CombatPayload.cast_id` is assigned per cast in `generate_hit_payload`); damage is `final_damage * damage_fraction * (1 + min(per_enemy_bonus * targets_caught, per_enemy_bonus_cap))`, where `final_damage` already includes a crit; the burst never crits and never triggers another burst (`CombatPayload.is_burst`); it carries only the cast statuses its definition lists in `carried_status_tags` (Task AH): a status is carried, with the cast's snapshots, only if at least one of its `granted_tags` is in the list; an empty list (the default) carries none, and a status with no granted tags can never be carried. `required_target_tag` is checked against the primary target before the hit's own statuses apply. An effect scene that extends `BurstEffect` receives a copy of the cast's payload through `configure` before it enters the tree; the copy is already marked `is_burst` with no bursts and no crit, and holds only the statuses `carried_status_tags` lets through, so an effect can never start a burst chain. `LingeringZone` (a `BurstEffect`, Task V) is a timed area that re-applies the cast statuses its burst definition lets through (`carried_status_tags`), with their snapshots and no direct damage, to enemies inside it; a new zone near a live one with the same `zone_id` refreshes it, and each `zone_id` has a live-zone cap. New shapes must only find targets; damage and recursion rules stay in the runner. `ImpactBurstDefinition.unlock_level` (default 1) gates a burst: the ledger's `get_impact_bursts` returns it only when its card's tier in that slot reaches it, through `IndirectScaling.is_unlocked`, the one level comparison shared with `IndirectScaling.is_active`. The shipped bursts are the Earth explosion (`resources/bursts/earth_explosion.tres`) and the Lightning overload (`lightning_overload.tres`), both level 3, and the compound bursts Shatter (`shatter.tres`) and Magma's lava zone (`magma_lava.tres`), both level 1 and carried by compound cards (see "Upgrade drafts"); all numbers placeholders. `ProjectileSpawnerComponent.projectile_impacted` is not used for this. A burst's size is the originating slot's `AOE_RADIUS` and `REACH_BONUS`, read from the caster's stats when the burst fires, times the shape's `radius_multiplier`. Damage and statuses carry over from the cast's payload; crit, speed and cooldown do not.
- **Indirect scaling and gating.** An infusion card may carry an `IndirectEffectDefinition` (`UpgradeDefinition.indirect_effect`) with its own `unlock_level`; it is active in a slot only when the card's level there (`get_card_tier`) reaches it, through the one gate `IndirectScaling.is_active`. Direct effects are never gated. Frost (cooldown shaved, with a 0.25 s floor in the calculation only) and Wind (`SPEED_BONUS`) give bonuses that are summed, clamped to +50% (`IndirectScaling.TOTAL_BONUS_CAP`) and applied once per cast, in `generate_hit_payload`, as `damage_scale` to the pre-crit hit damage and to the DoT snapshot (each hit's crit and `CRIT_DOT_SHARE` apply afterwards, per hit); duration, ramp cap and bursts are not rescaled. All numbers are placeholders.

## Append-only enums
`Stat.Type`, `Tags.Type`, `UpgradeDefinition.PayloadType`, and any other enum referenced from `.tres` files are stored as integers. Add new entries at the END only. Never insert, reorder, or delete entries. `Stat.Type.STATUS_STACK_BONUS` (20) is deprecated and unused (Task AK); it stays so stored integers remain valid.

## Run persistence
Room scenes are freed on every transition, so run state lives in `RunSession.state` (a `RunState` resource).
- `Player._exit_tree` captures it (skipped if the player is dead). `Player._ready` restores it before `player_spawned` is emitted. `MapGenerator` resets it when a new run starts.
- Any NEW state that must survive rooms needs three edits: a field in `RunState`, capture in `Player.capture_run_state`, restore in `Player._restore_run_state`.
- Exception: `UpgradeManager` lives under the Systems node of the World scene (freed with it). It writes `RunState.pending_draft_levels` through to `RunSession.state` on every queue change and reloads it in `_ready`.
- Not persisted on purpose: status effects, temporary modifiers, cooldown timers, uncollected pickups, offer drafts (eligibility is derived from persisted state).

## Upgrade drafts, evolution and Overclock
- **Level-up drafts** never contain infusion cards, evolution cards, Overclock cards or compound cards.
- **Infusion drafts** are separate from level-up drafts (`UpgradeManager.trigger_infusion_draft_event`). Only elements that at least one ability can accept are offered. When infusion drafts happen in a normal run is undecided; today it is triggered only from the debug panel (F1, Run tab). The infusion card in the pool is global. The per-element ceiling is enforced per ability by `InfusionTrackerComponent.is_element_socket_allowed`, not by the profile's `total_tiers`.
- **Offer drafts.** When an ability reaches its soft cap (`EvolutionGateComponent.is_offer_eligible`), `UpgradeManager` presents a forced draft for it: every form evolution card that matches, then Overclock; when the slot has a compound pair (see "Compound cards"), the pair's two compound cards replace the generic Overclock. No decline, no reroll, no random fill. Checked after each confirmed infusion and at room start, before queued level-ups. Never stored.
- **Evolution cards** are `ABILITY_UNLOCK` definitions with `evolves_from` (the ability's current `AbilityData`, compared by `resource_path`) and `recipe_requirements` (elements that must be at the soft cap). These are form evolutions: they swap the ability's strategy nodes. Compound evolution cards are different (next bullet).
- **Overclock** is a generic `ABILITY_OVERCLOCK` card, logged per slot with `log_slot_specific_purchase`. It lifts only the per-element cap (3 or 5 -> 15). The element-count limit still applies. Whether a slot is overclocked is stored nowhere else: `RunLedgerComponent.is_overclocked(slot)` is true when the slot-specific purchase of an `ABILITY_OVERCLOCK` card is above 0, and `EvolutionGateComponent.is_permanently_overclocked` is a read-only answer from the ledger (wired by `configure_slot_context(slot, ledger)`, like the infusion tracker). A plain (non-slot) purchase overclocks nothing.
- **Compound cards (Task AI, decided Oct 25).** A compound is a fixed element pair with no infusion level and no tag. A compound card is an `UpgradeDefinition` with `compound_pair` (exactly two elements; `is_compound_card()`), usually carrying an `impact_burst_payload`, and, for a compound without Fire, optionally one `status_effect_payload` (Shatter carries Chill). Compound cards exist only in the forced offer (never in level-up drafts or the debug grant list). `UpgradeManager.get_compound_pair(ability)` returns the pair only when the gate is TIER_1_BASE and exactly two elements are active, both at level 3. When the pool has compound cards for that pair, the offer is: form evolution cards first (if any), then the pair's two compound cards, and the generic Overclock is dropped. The two cards are "Evolve + compound" (`ABILITY_UNLOCK`, no `evolves_from`, no ability data) and "Overclock + compound" (`ABILITY_OVERCLOCK`); the effect is identical on both. Applying either logs it as a slot-specific purchase (`log_slot_specific_purchase`), so the effect reaches only that slot. "Evolve + compound" also calls `advance_evolution_state` on the slot's gate with no ability swap (`Player.apply_contextual_upgrade`). "Overclock + compound" goes through the normal Overclock branch, so `is_overclocked` is true. A card already bought for the slot is not offered again. A pair with no compound cards offers form evolutions plus the generic Overclock as before. One pair of cards per compound serves every ability. Compounds at tier 2 are not built. Shipped: Shatter (Frost + Earth) and Magma (Fire + Earth), under `resources/compounds/`.
- Plasma (Fire + Lightning) is a form evolution, not a compound card: its effect is the `CRIT_DOT_SHARE` stat on the evolved profile (Task R, per hit since Task AL). A critting hit multiplies its own Burn snapshot by `1 + (CRIT_MULTIPLIER - 1) * CRIT_DOT_SHARE`. Only an evolved profile sets it, so a Fire + Lightning slot that takes the generic Overclock gets no Plasma effect (GDD item 57). A `PLASMA` tag is added only when a card needs to target Plasma abilities.

## Combat design decisions
- Two separate damage channels. **Hit** uses `BASE_DAMAGE`, crit chance and crit multiplier. **DoT** uses its own `DOT_DAMAGE` and `STATUS_DURATION`. DoT never reads `BASE_DAMAGE`, and DoT ticks never crit.
- Fire is the DoT element (duration theme). Lightning is the hit element (crit theme).
- **Two stats on every ability.** Every ability profile carries a nonzero `BASE_DAMAGE` and a nonzero `DOT_DAMAGE`. `DOT_DAMAGE` is inert potency: nothing ticks until a status with a duration is applied. There is no cast-time duration gate. `StatusEffectComponent.apply_effect` returns early when the effective duration (template `base_duration` plus the `STATUS_DURATION` bonus) is 0 or less, so there is no instance, no tag, no ticks and no warning.
- **Fire deals no damage itself.** Per level it adds flat `STATUS_DURATION` (+3.0 s) and flat `STATUS_RAMP_CAP` (+0.1). Flat modifiers scale as `value * tier`. The cap bonus flows through `status_ramp_cap_snapshot` to `StatusEffectInstance.ramp_cap_bonus`, the same path as `duration_bonus`, and a re-apply takes the new application's value only when it wins (see "Re-applying a status"). Burn's template `base_duration` is 0, so duration comes only from Fire. A card carries all its stat modifiers in one ordered list, UpgradeDefinition.stat_modifiers (Fire has two). All numbers are placeholders.
- **Indirect infusion scalings** unlock by infusion level and boost both channels through a cast-time `damage_scale` applied to the pre-crit hit damage and `dot_damage_snapshot` (indirect bonuses summed, then capped at +50%). Frost: bonus per 0.1 s shaved off the default cooldown (level 2). Wind: speed ratio, with one generic speed stat read by every driver (level 2). Lightning (overload on crit, level 3) and Earth (on-impact explosion scaling with enemies caught, level 3) share the impact-burst mechanism (see Architecture rules). Burst effects scale off hit damage.
- Area abilities read `AOE_RADIUS` for their reach, and projectile and orbit hitboxes read it too. Chain link keeps `QUERY_RADIUS` / `CHAIN_RADIUS`, and projectile targeting keeps `QUERY_RADIUS`.
- Infusions contribute through stat modifiers (UpgradeDefinition.stat_modifiers). Only the Fire infusion card carries a status (`status_effect_payload`, Burn). Other statuses are carried by compound cards (see "Status sources"). Effect templates define shape only (tick interval, ramp), never absolute damage.
- Card scaling is multiplicative, per card: the ledger multiplies `pow(1.0 + value, tier)` for each card, where tier is the card's duplicate count. Final stat = `(base + flat) * (1 + percent) * multiplicative`. This was the one rule that made both specializations viable in the balance workbook.
- **Re-applying a status (Task AK, decided Oct 26).** Statuses never stack: there is one `StatusEffectInstance` per effect per target, and `StackingPolicy`, `max_stacks`, the `stacks` count and the stack-cap snapshot no longer exist (`Stat.Type.STATUS_STACK_BONUS` is deprecated). Re-applying an active ticking status: the strongest application wins. If the new `dot_damage` is at least the existing one (a tie takes the newer), the new `dot_damage`, `duration_bonus` and `ramp_cap_bonus` are adopted as a unit; otherwise the existing unit stays. Either way `elapsed` is kept (the ramp keeps running), `refreshed` is emitted, and the timer becomes the longer of the time left and the new application's effective duration, so a weaker or shorter application never shortens it. A non-ticking status (Chill) adopts the latest values and resets its timer. Tick damage is `dot_damage * ramp * interval`. A strong Burn (for example a crit-boosted Plasma Burn) therefore lasts until it expires. Fire stays build agnostic.
- Status effect templates are never mutated. Runtime state lives in `StatusEffectInstance`. Statuses are not persisted between rooms. Burn ramp is +10%/s capped at +50%, matching the workbook. All other Burn and Chill numbers are placeholders.
- All numbers in the balance workbook are placeholders.
- **Status application rules.** Any `UpgradeDefinition` can carry a `status_effect_payload`, resolved through the ledger with the normal scope rules and deduplicated by `effect_id`. Statuses are chosen at cast time and applied on every hit (no chance stat). A ticking status is skipped when the ability's `DOT_DAMAGE` snapshot is 0. `STATUS_DURATION` is ability-wide. A status whose effective duration is 0 or less is not applied at all. No status variants.
- **Status sources (decided Oct 26).** Fire is the only base infusion that applies a status (Burn). Every other status comes from a compound card. A compound that includes Fire carries no status of its own: the ability's status is Burn, and the compound may use, spread or amplify it. A compound without Fire carries at most one status. Together these give at most one status per ability at tier 1; the tier 2 rule is open (GDD item 54). Shipped: Burn (Fire card), Chill (both Shatter cards, since Task AO). Do not add a `status_effect_payload` to a base infusion card.
- **Status duration and magnitude (decided Oct 27, Task AR).** Two ability-wide stats scale a status. `STATUS_DURATION` adds seconds to the template's `base_duration`. `STATUS_MAGNITUDE_BONUS` (default 0.0, the REACH_BONUS pattern) scales a non-ticking status's `stat_modifiers` values by `1 + bonus`, snapshotted at cast time (`CombatPayload.status_magnitude_snapshot`) and clamped to `0..StatusEffect.max_magnitude_bonus` (placeholder 0.5). A template opts in with `magnitude_scales` (Chill does; Burn does not). Burn's strength stays `DOT_DAMAGE` plus `STATUS_RAMP_CAP`; magnitude never touches ticking damage. A status that has no scalable magnitude reads duration only. Cards raise these stats as ordinary stat cards; there is no special status draft.

## Working in this repo
- Before changing a method signature, grep all `.gd` AND `.tscn` files for callers.
- Be careful with `.tscn` / `.tres` edits: they hold resource IDs and enum integers. Keep diffs small and review them.
- Prefer editing existing files over creating new ones. Do not add features that were not asked for.
- Debug tools live in `res://debug/` behind one panel (`DebugHub`, F1, debug builds only). Put the logic of a new debug action in `DebugActions` as a static function with a logic check, and add its button to the panel. Do not add other hotkeys or separate debug nodes to scenes.
- Do not claim something works unless it was actually run, and say which kind of run it was (Verified or Headless).
- Headless checks (Godot 4.5; `$GODOT` is `C:\Users\chris\Desktop\Godot_v4.5-stable_win64.exe`; run from the project root):
  - Import / project scan: `$GODOT --headless --path . --import`
  - World run (600 frames, read the errors; about 4 s): `$GODOT --headless --path . res://scenes/world/world.tscn --quit-after 600`
  - Load check: `$GODOT --headless --path . -s res://tools/headless/load_all.gd`. It tries to open every `.gd`, `.tscn` and `.tres` outside `addons/` and `tools/`, which catches parse errors and broken references. It skips `res://tools/`, because it crashed Godot by reloading itself. The latest count is in `STATUS.md`.
  - Logic test: `$GODOT --headless --path . -s res://tools/headless/runner.gd`. Each `check(...)` is one assertion about behavior; the latest count is in `STATUS.md`. It runs `res://tools/headless/logic_test.gd` unless the `LOGIC_TEST` environment variable names another script. It prints `ERROR: N resources still in use at exit` (N grows when a check creates objects it does not free) because the harness quits early; that is expected.
  - These checks do not use GUT (`addons/gut`), and the GUT folder does not run them.
  - Error guard (Task AA): every section of the logic and golden tests runs under an error capture (`tools/headless/error_capture.gd`, Godot's `Logger`). An engine ERROR or script error printed during a section fails that section with one check named `error guard <section>`; warnings are counted and printed, not failed. An error that is known and accepted goes in `tools/headless/expected_errors.gd` with a section, a message fragment, a maximum count and a reason; a new section that deliberately triggers an engine error must add one. The 600-frame world run has a pass or fail version: `LOGIC_TEST=res://tools/headless/world_smoke.gd $GODOT --headless --path . -s res://tools/headless/runner.gd`. A bug fix needs a check that fails without the fix; a printed error counts as a failure only through this guard.
  - Golden test: `LOGIC_TEST=res://tools/headless/golden_test.gd $GODOT --headless --path . -s res://tools/headless/runner.gd` (same runner, with the `LOGIC_TEST` environment variable naming the golden script).
